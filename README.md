发布前运行 `powershell -ExecutionPolicy Bypass -File app/launcher/prepare-release.ps1`，只上传生成的 `release/Miliastra-Wonderland-Comment-Collector-日期时间/` 目录内容。发布副本不包含个人评论、便签、关卡登记、代理或 Cookie 配置；请勿直接拖拽整个日常使用目录到 GitHub 网页上传，网页上传不会替你应用 `.gitignore`。

## 同组全部区服评论总览

展开顶部关卡选择器中的项目分组，第一项“分组名 · 评论总览”会合并显示该组各区服已保存的评论；下面保留各区服的独立入口。空白、未导入的区服不属于同步目标。

总览以缩进子项显示在分组下，与各区服同级，统一显示“分组名 · 评论总览”和评论条数；顶部收起后的选择栏也保留分组名。长文案会换行。支持鼠标或键盘 Enter/空格打开。移除部分区服后自动更新总览成员与条数；整组改名或并入已有组时继续显示新组总览。当前组消失时回退到可用单服；全部清空后清除列表并禁用同步按钮。同步期间切换总览或单服不会重新启用同步按钮。

组合回归覆盖与运行命令见 [测试说明](app/docs/TESTING.md)。

选中总览后，主同步按钮更新本组所有已登记条目，全量同步同样作用于本组；同步后保持在总览。部分区服同步失败会显示错误，成功区服仍正常更新，失败区服保留原有本地数据。总览读取任一成员文件失败时会报错，不把不完整数据当作完整结果展示。

搜索、评价/模板筛选、日期筛选、统计、排序和 CSV 导出均作用于合并列表。每条评论标注来源区服；时间排序按评论时间，合并好评率按本地评论计算。评论不会因跨服同 ID 或相同文本被合并删除。CSV 增加关卡和区服列；收藏仍写回原关卡，便签定位会返回原单服。总览不创建新的存储目录，不改变现有分组和评论文件。

## 启动程序

本地服务会校验回环 Host、实际端口、浏览器 Origin 和跨站请求元数据，修改数据的接口要求 JSON；关页信标保留兼容处理。请使用启动器给出的本地地址访问。评论和便签 CSV 会为可能被表格软件当作公式的内容添加前置单引号，导出结果可能显示该安全前缀，原评论和备注不会改变。这些保护不替代操作系统的本地进程权限控制。

在 Windows 下双击 **Miliastra Wonderland Comment Collector.exe**。它会隐藏控制台并打开默认浏览器，无需管理员权限。必须保留同目录完整的 `app/`；已有的 `config/`、`data/` 是用户数据，不要删除。首次使用缺失的数据目录会按需创建。EXE 是启动器，不是单文件安装包。

需要支持内置 fetch 的 Node.js（18 或更新版本）以及可用的 Windows curl。可以安装 Node.js 并加入 PATH，也可以将 `node.exe` 放在工具根目录或 `runtime/node.exe`。

正常地址为 `http://127.0.0.1:8788/`；端口被占用时会尝试其他端口。关闭工具页面后，自动退出模式通常在短暂宽限期后结束后台服务。管理页可切换常驻。

兼容启动文件位于 `app/启动.cmd` 和 `app/启动.vbs`。需要诊断输出时，在工具根目录终端运行 `app/启动.cmd --console`。更新前端后用 Ctrl+Shift+R 强制刷新；修改后端后还需重启服务。

## 六步实操教程

首次打开会引导：选择语言 → 真实添加并同步 → 标签筛选 → 星标收藏 → 写备注并确认保存 → 功能回顾。

请填写自己的关卡 ID 或分享链接。停止输入约半秒会自动查询；切换区服会重新查询，也可点击查询或按回车。确认预览后，添加与同步会实际登记关卡并下载评论。

只有本地确实有评论、实际保存了便签和非空备注，教程才会完成。同步失败或零评论时留在导入步骤。金色呼吸光圈、箭头和步骤文字标注操作目标；系统开启减少动态效果时使用静态高亮。

最后一步会提示使用 Chrome 等浏览器的翻译功能或翻译插件阅读多语言评论。此工具本身负责界面本地化，评论翻译由使用者选择的浏览器功能处理。

可选择稍后再看；已有数据会保留，已开始的同步继续运行。右上角新手引导可重新打开。完成或暂时退出后，该浏览器不再自动弹出；教程版本、浏览器、端口变化或清理浏览器数据后可能再次出现。

## 添加关卡

简体中文默认国服入口；其余语言（包括繁体中文）默认国际服入口，均可手动切换。

| 平台 | 区服代码 |
|---|---|
| 国服 · 米游社 | `cn_gf01`（天空岛）、`cn_qd01`（世界树） |
| 国际服 · HoYoLAB | `os_asia`、`os_euro`、`os_usa`、`os_cht` |

支持纯数字 ID、含 `level_id=` 的网页链接及含 `id=` 的游戏分享链接，也支持编码链接与全角数字。纯 ID 必须选择正确区服。格式错误、官方返回不存在或拒绝访问、无代理及网络失败会分别提示；网络失败不代表 ID 无效。

国服名字搜索通过米游社帖子寻找分享链接，不是完整的关卡目录；没有结果时可以尝试 ID 或分享链接。国际服使用 ID 或链接添加。

同一关卡不同区服的 ID 可能不同。条目按区服与 ID 判重，分组使用 `config/games.json` 的显式 `group` 字段。管理页可以改组、并组或拆组。

### 多服一次导入

在添加奇域中点击一次导入多个区服。每服填写各自 ID 或分享链接，没有发布的区服留空；取消导入此项会保留输入但跳过查询与导入。

每栏自动查询并显示预览。首个成功查询的名字自动填入分组，其他名字加入候选。点击分组输入区域任意位置可展开全部已有分组和查询名字，也可以直接编辑。自定义内容会保留，清空后恢复自动名字。

链接区服与栏位不符时会提示。首次保存后，本轮分组锁定；失败项可修正重试，成功项不会重复提交。需要调整已保存条目的分组时使用管理页。

默认导入成功后关闭弹窗；勾选导入后保持窗口打开则保留。存在导入失败项时也会保留窗口。勾选导入后同步评论时，只同步本次成功登记的条目；同步失败会保留登记，便于之后重试。

## 评论、筛选与同步

- 同步最新：刷新主评论索引并合并新评论，自动分页检查、保存子评论；为发现旧评论下的新回复，也会复查旧楼层，因此可能比旧版耗时更长。
- 全量重抓：重新获取并刷新已有内容；只有本轮覆盖满足服务端总数条件时才清理未返回的旧评论。
- 本组更新／本组全量同步：处理当前分组的所有登记条目，某一服失败后继续其他服，并显示部分失败。
- 支持昵称、正文、评论编号和 IP 归属地搜索，以及时间、点赞、长度、子评论数量排序；日期起止均含当天，允许只填一端。
- CSV 按当前筛选结果导出。官方好评率与本地评论计算的比例可能不同。

好评／差评来自官方 `is_recommend`，不靠词语猜测情感。默认评论识别结合已知多语言规则与重复频次，可能漏判或误判。默认模板阈值为 8，已知规则不受此频次门槛限制。过滤默认会隐藏纯模板，保留被识别为玩家补充的文字。

接口分页、热门序、隐藏或已删除评论及子回复预览可能影响完整性。耗时随网络和数据量变化，不保证固定秒数或 100% 覆盖；嵌套回复也可能不完整。

## 便签

点击评论右上角 ☆，保存评论快照；已收藏显示 ★，再次点击可移除。便签跨所有登记关卡显示，可平铺、按关卡、关卡加区服或仅区服分组。

备注约 0.6 秒自动保存，离开输入框会提前提交。重新渲染时会保留当前页草稿，保存失败会提示；关闭或刷新前请等待保存完成。连续保存与删除按条目排队，避免旧请求覆盖新内容。

定位到评论会切换对应关卡并高亮。便签 CSV 包含来源关卡、区服、评论信息、备注及原文；导出前会等待当前页备注保存。时间统一按设备本地时区显示。

## 管理与删除

管理页显示登记、评论及便签数量、占用、上次同步、本机目录与常驻设置。

仅移除登记保留本地文件；彻底删除会清理该条目或整组的评论、便签和本地文件。请阅读确认提示，删除前自行备份。同步过程中会阻止移除和删除，避免文件被未结束的同步重新写回。

不同名称即使因 Windows 字符替换、大小写或空格产生相同目录名，新登记也会进行区分。保留的旧数据只在能够确认同一区服及 ID 时复用。JSON 保存采用临时文件替换；损坏文件会报错，不自动当作空集合覆盖。

## 子评论与新增提醒

普通同步会按官方 `parent_reply_id` 子评论接口逐页保存可访问的回复，不再只保留主列表内联的前两条预览；国服和国际服使用各自对应服务。默认最多同时处理 3 个评论串。每串有 30 秒、50 页、1000 条保护上限；重复游标、接口错误或达到上限会标记未完成，不冒充全部完成，保留已有正文并允许单独刷新。累计失败达到 3 次会停止继续批量尝试，并标记剩余评论串未完成。官方未开放、隐藏或删除的内容仍无法保证取得。

回复串默认收起，摘要显示回复数量和新回复提醒，点击展开/收回；嵌套返回或 `r_user` 回复对象会显示层级或回复目标。正文已保存在 `comments.json`，展开不依赖网络；“刷新此评论的全部回复”才重新联网。CSV 增加子评论数量和已加载子评论文本列。

同步完成提示新增评论/子回复数量；新评论卡片、新回复正文与收起摘要会高亮。更新标记保存在各关卡评论文件中，查看不会清除；重开后第一次完整成功同步会自动开始新一轮。点击“清除更新标记”只清除当前单服或当前总览组的提示，不删除正文或便签。这里的“新”指本地首次收录；首次导入会将导入内容标为新，并不代表都刚刚发布。

## 外观设置

切回默认皮肤会同时清除预设写入的页面、文字、控件及色彩模式变量，避免明亮与夜色混用。主评论昵称和回复者使用强调色，回复对象使用较弱的文字色，正文单独显示；回复串摘要保留父楼层和父评论昵称，方便确认归属。接口提供的关卡/父评论字段与当前请求不一致时，收集器会拒绝写入。

“外观”页提供 10 套主题：默认夜色、星海鲸蓝、森野嫩绿、素净晴日、灯火暖红、水光冰蓝、樱花柔粉、和风纸笺、紫电绮夜、岩金雅境。可点击配色预览卡切换，各主题使用不同的背景纹理、边框或圆角；背景、面板、评论卡片、强调色和文字仍可单独调整。

提供 12 种背景动画：蓝鲸、爱心、星星、暖光蝴蝶、水滴气泡、草叶、花瓣、雪花、紫电、灯笼、科技方晶、梦幻银蝶。采用本地 SVG 图形，未包含参考图的人物立绘或官方标志。旧版河豚选项自动迁移为蓝鲸。粒子均匀错相，修改颜色不会重新启动动画；默认关闭，装饰层不接收点击，后台标签页暂停，系统减少动态效果时隐藏。可一键恢复默认。设置只保存在当前浏览器，不写入评论目录，也不会随 GitHub 上传副本传播。自行配色时请注意文字与背景的对比度。

更新评论和更新回复合计放在筛选栏内；新评论徽标、更新回复串边框及展开后的更新回复分别标注，不额外占用一整行。

## 网络与代理

无论本机在哪个地区，国服和国际服在正常自动模式下优先直连；近期成功路线可能被缓存。网络故障或地区拦截时会寻找本机已有代理，并记录过程。

候选顺序为显式 `--proxy`／环境变量（`QXQY_PROXY`、`HTTPS_PROXY`、`https_proxy`、`ALL_PROXY`、`all_proxy`）、Windows 系统代理、`config/proxy.txt`、本机常见代理端口。自动候选失败时会暂时跳过并尝试其他候选；官方业务错误不会因此误封正常代理。诊断用 `QXQY_ROUTE=direct` 或 `proxy` 会强制路线，取消自动回落。

通常启用代理客户端的系统代理即可。也可在 `config/proxy.txt` 提供一行候选，例如 `http://127.0.0.1:10808`。这是本机回环地址示例，不是提供的代理服务；支持 HTTP 与 SOCKS5。工具不提供客户端、节点或订阅，没有可用路线时会明确报错。

## 文件、命令与构建

程序主体由 EXE 和 `app/` 构成，日常配置与评论保存在 `config/`、`data/`。发布还包含许可证、版本说明及校验文件，完整清单见 [交付指南](app/docs/RELEASE-CHECK.md)。常用路径如下：

| 路径 | 内容 |
|---|---|
| `app/` | 页面、译文、教程、导入与便签逻辑、本地服务、图标 |
| `app/launcher/` | EXE 源码、清单与构建脚本 |
| `app/tests/` | 单元与隔离端到端测试；其中模拟远端接口，不改工作数据 |
| `app/docs/API.md` | 本地 API 与存储行为说明 |
| `config/games.json` | 登记和分组 |
| `config/proxy.txt`、可选 `config/cookie.txt` | 本机代理与可选凭据；公开评论通常不需要登录 |
| `data/<关卡名>/comments.json`、`notes.json` | 评论与便签 |

在根目录可运行：

```text
node app/collect.js list
node app/collect.js add "示例关卡" <ID或链接>
node app/collect.js sync [名字] [--full]
node app/collect.js remove "示例关卡" [--data]
node app/collect.js proxy
node app/collect.js templates
node app/server.js [--port 8788] [--no-open] [--stay]
node --test app/tests/*.test.cjs
```

`remove --data` 会删除数据。Windows PowerShell 可运行 `app/launcher/build.ps1`，使用已安装的 .NET Framework C# 编译器生成启动 EXE，无需下载构建包。更多技术说明见 [API 文档](app/docs/API.md)。

## 备份和分享

暂停同步及备注编辑后，将 `config/games.json` 与整个 `data/` 一起备份到另一位置。

分享时制作独立副本，检查或排除评论、登记、便签、导出 CSV、日志和截图；这些可能包含昵称、UID、IP 归属地和个人备注。不要为了制作副本删除工作数据。副本不要附带 `config/cookie.txt`，并清空个人代理地址、账号或密码。

管理页会显示本机路径，截图前请检查用户名和目录信息。文档使用通用路径与示例，不应填入个人凭据。请遵守平台规则，并尊重其他用户的内容与隐私。

## 更新评论、更新回复与悬浮反馈

“更新优先”默认开启：带更新标记的评论、含更新回复的楼层优先显示；时间从新到旧排序下，使用可获取的更新评论／回复发布时间安排更新区。关闭后恢复原有排序。“只看更新”与搜索、评价、默认评论及时间筛选共同生效；需要时保留未标记的父级作为回复上下文。导出评论 CSV 使用同样的更新筛选和回复上下文规则。

更新标记保存在各关卡的 comments.json 中。每次重新打开或刷新页面后，各关卡第一次完整成功同步会自动清除上一轮标记，只保留本轮收到的新评论和回复；本次打开中的后续同步继续累积。网络失败或回复未取完时不清旧标记，重试成功也会保留本次打开中已经收到的新内容。分组里各区服分别处理，失败区服不会因其他区服成功而被清除。

“清除更新标记”按钮与更新数量放在一起，有可清除内容时使用强调色并显示数量；无内容或同步期间禁用。它作用于当前关卡，总览下作用于整组，不受搜索等筛选限制，不删除评论或便签。同步状态另显示“本次同步新增”数量。更新优先每次打开默认开启，只看更新每次打开默认关闭。此版本修改了后台逻辑，更新后需要重启服务并强制刷新页面。

子回复取消无区分的返回箭头，将作者、回复对象和正文分开显示；真实嵌套数据逐层缩进。悬浮或键盘聚焦回复行，会高亮被回复用户在同一串中的发言。有些接口只提供目标用户，没有精确目标回复 ID；同一用户有多条发言时可能同时高亮，不能据此认定某一条是父回复。

外观页可选择自动悬浮反馈或自定义悬浮背景色，并提供预览按钮。自动模式跟随主题及好评／差评等按钮语义颜色；自定义模式自动选择黑／白文字。悬浮颜色独立于常态配色，保存在当前浏览器；恢复默认会回到自动模式。禁用按钮不显示可点击的悬浮反馈。

评论与子回复正文明确允许浏览器翻译，但工具本身不提供机器翻译。短词、人名或无法识别的内容可能被翻译服务原样保留，不能保证“Yuiop”等文本会产生译文。可选中文字使用 Chrome 的“翻译所选内容”；参见 [Chrome 官方翻译说明](https://support.google.com/chrome/answer/173424?hl=zh-Hans)。原始本地评论不会因此改写。


更新评论／更新回复表示同步中新保存到本地、尚未清除标记的内容，不表示是否阅读，也不表示原作者编辑过正文。单纯查看或展开不会清除标记。“清除更新标记”不会删除任何评论或回复。旧版内部存储字段仍保留 unread 命名，以兼容已有评论文件，无须迁移数据。

直接回复主评论的行不再显示“回复主评论”标签；只有接口明确提供回复对象时才显示“回复某某”。“过滤默认”的未选中、选中、悬浮和键盘焦点均跟随主题；自定义悬浮色也适用于此控件。

向下滚动进入阅读区时，顶部工具栏会向上收起；向上滚动或回到顶部时恢复。菜单、弹窗、新手教程和键盘导航期间保持操作入口可用；小幅滚动有防抖，系统减少动态效果时直接切换。此行为适用于桌面和窄屏。
